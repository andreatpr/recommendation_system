# City Discovery Engine

Travel-oriented recommendation system built on the Yelp Academic Dataset. Academic project
(course milestones W3–W15): notebooks train a hybrid recommender, and a FastAPI + Next.js
MVP serves it as an interactive web app.

## Project Structure

```
data/
  raw/          ← original Yelp JSON (not included, see Dataset below)
  processed/    ← parquet/pickle artifacts generated by the notebooks
                   (data/processed/models/hybrid_artifacts.pkl is the trained model served by api/)
notebooks/
  pre.ipynb                ← data preprocessing (Week 3)
  week5_modified.ipynb     ← feature engineering / PCA (Week 5)
  week7.ipynb              ← KMeans / DBSCAN clustering (Week 7)
  w10.ipynb                ← hybrid recommendation model (Week 11)
  week12.ipynb             ← graph analytics and centrality (Week 13)
api/            ← FastAPI backend serving hybrid_artifacts.pkl, with Swagger docs and tests
web/            ← Next.js frontend to try the recommender interactively
reports/        ← graded assignment reports (Weeks 3, 5, 7, 11, 13)
docker-compose.yml
requirements.txt   ← notebook/training environment
README.md
RUNBOOK.md
```

## Dataset

Yelp Academic Dataset — https://www.yelp.com/dataset
Requires a free academic sign-up. Original files aren't included in this repo due to license
restrictions.

Download and unzip into `data/raw/`. Required files:
- `yelp_academic_dataset_business.json`
- `yelp_academic_dataset_review.json`
- `yelp_academic_dataset_user.json`
- `yelp_academic_dataset_checkin.json`

## Reproducing the notebooks

1. Install dependencies: `pip install -r requirements.txt`
2. Place the Yelp JSON files in `data/raw/` (or upload to `drive/MyDrive/Yelp JSON/yelp_dataset/`
   if running on Colab)
3. Run the notebooks in order: `pre.ipynb` → `week5_modified.ipynb` → `week7.ipynb` → `w10.ipynb`
   → `week12.ipynb`. Full pipeline details in `RUNBOOK.md`.

`w10.ipynb` trains the hybrid model (collaborative filtering + content-based + popularity) and
saves it to `data/processed/models/hybrid_artifacts.pkl` — this is the artifact the MVP below
serves; no training happens in `api/`.

## Week 15 — Final Delivery (MVP)

The trained model is served through a FastAPI backend (`api/`, Swagger at `/docs`) and a
Next.js frontend (`web/`) to try recommendations interactively.

```bash
docker compose up --build
```

- Web app: http://localhost:3100
- API + Swagger: http://localhost:8000/docs

See `api/README.md` and `web/README.md` for endpoint/component details.

### Main flow — recommend by preferences

The primary UX (`web/` "Tus gustos" tab) doesn't require knowing a Yelp user id: pick 3-5
cities you know from a searchable catalog, rate them with stars, and get personalized
recommendations (`POST /recommendations/preferences`). Under the hood: a content profile is
built as the weighted average of the rated cities' embeddings (weight = rating × reviews
signal), then blended with global popularity — no collaborative-filtering factors are needed
since a brand-new user has none.

### Academic demo mode — full hybrid model

A secondary tab ("Modo demo académico") exercises the complete hybrid system (collaborative
filtering + content-based + popularity) against real dataset users via `GET
/recommendations/{user_id}`. Typing an unknown/made-up id demonstrates the cold-start
fallback: the API automatically returns a popularity-based ranking (`method: "popularity"`,
`is_cold_start: true`) instead of erroring.

### How to test the MVP

1. **Start everything**: `docker compose up --build` (first build takes a few minutes). Wait
   until both services are healthy.
2. **Web UI** (http://localhost:3100):
   - "Tus gustos": search and pick 3-5 cities (autocomplete over the 213-city catalog), rate
     each with stars, press "Ver mis recomendaciones". Compare the personalized column against
     the popularity baseline.
   - "Modo demo académico": pick a sample user, or type a made-up id to see the cold-start
     fallback banner.
   - `/catalog`: enriched city cards (avg rating, reviewer counts, "Popular"/"Joya oculta"
     badges) filterable by cluster.
3. **Swagger** (http://localhost:8000/docs):
   - `POST /recommendations/preferences` with e.g.
     `{"preferences":[{"city":"west chester","rating":5}],"k":10}` → `method: "preferences"`
     (valid city names come from `GET /cities`).
   - `GET /users/sample` → copy an id → `GET /recommendations/{user_id}` → `method: "hybrid"`.
   - Same endpoint with a made-up id (e.g. `test-123`) → `method: "popularity"`,
     `is_cold_start: true`.
   - `GET /model-info` → hybrid weights, reported metrics (Recall@4: 12.8% baseline → 52.1%
     hybrid) and `data_quality` flags (documents the approximations used where the original
     `w11/` training artifacts aren't resolvable in this repo — see `api/README.md`).
4. **Automated tests**:

   ```bash
   cd api
   pip install -r requirements-api.txt
   pytest        # expected: 25 passed
   ```

   Or inside Docker: `docker compose run --rm api pytest`.
